# TimeWeaver — Limitless File Metadata Editor

A Windows desktop application for viewing and modifying real filesystem metadata —
creation time, last modified time, last accessed time, and Windows file attributes —
with a dark VS Code-inspired interface and support for large directory trees.

## Purpose

Windows Explorer exposes only basic file properties. TimeWeaver provides a dedicated,
performant interface for inspecting and editing the full set of file-system timestamps
and attributes that the NTFS filesystem stores but typical tools hide or restrict.

It is designed for developers, system administrators, digital forensics analysts, and
anyone who needs to repair incorrect timestamps, reset file attributes in bulk, or
explore the rich set of Windows Shell extended properties that the operating system
attaches to every file and folder.

## Features

- **Filesystem Tree Browser** — open any folder as the root and navigate its hierarchy via an interactive tree view with five columns: Name, Size, Type, Modified date, and Attributes.
- **Timestamp Editing** — view and modify Creation, Modified, and Accessed timestamps for any file or folder using a calendar date-time picker.
- **Windows File Attributes** — toggle Read-only, Hidden, System, and Archive flags through checkboxes with bitmask-based persistence.
- **Recursive Operations** — apply timestamp changes to an entire directory tree in a single operation.
- **Extended Shell Properties** — lazy-load up to 320 Windows Shell properties per file (e.g., Authors, Copyright, Camera model, GPS coordinates, EXIF data) via the `Shell.Application` COM interface, displayed in a searchable tab.
- **Inline Rename** — rename files directly in the tree view (F2 or slow double-click).
- **Multi-threaded Operations** — extended property loading and save operations execute on background threads via `QThread`, keeping the UI responsive.
- **Dark Theme** — VS Code-inspired dark colour scheme with custom stylesheet covering all widgets, scrollbars, splitter, tabs, and selection states.
- **Standalone Executable** — bundled via PyInstaller into a single `.exe` with zero runtime dependencies; distributable to any Windows machine without Python or Qt.
- **Portable Build Pipeline** — one-click `MakeExecutable.bat` script that creates a virtual environment, installs dependencies, builds the executable, and packages it into a portable folder.

## Architecture

### High-level design

The application follows a conventional **Model-View** pattern on top of Qt:

1. **Model** — `FileTreeModel` (tree) and `FileInfo` (node data) form the data layer. `FileInfo` wraps `os.stat`, `win32api.GetFileAttributes`, and lazily-loaded COM shell properties.
2. **View** — `QTreeView` displays the model. `QTabWidget` + custom form layout displays the currently selected item's details.
3. **Controller logic** — Lives in `MainWindow` slot methods (`on_selection_changed`, `on_save`, `on_open_folder`). Background work is delegated to `QThread` subclasses to avoid blocking the GUI thread.

### Request / Data flow

```
User clicks "Open Folder"
  └─ QFileDialog.getExistingDirectory
      └─ FileTreeModel(root_path)
          └─ TreeItem(root_item)
              └─ _load_children (lazy: only immediate children)

User expands a tree node
  └─ rowCount called → _load_children triggered if not _loaded
      └─ fs_logic.get_directory_contents → [FileInfo, ...]
          └─ TreeItem child nodes created

User selects a tree item
  └─ on_selection_changed
      ├─ update_details_ui (synchronous, fills timestamps + attributes)
      └─ load_extended_properties (async via PropLoadWorker)
          └─ FileInfo.load_extended_properties (win32com Shell.Application)
              └─ on_props_loaded → fill_prop_form

User clicks "Apply Changes"
  └─ on_save
      └─ SaveWorker (QThread)
          ├─ fs_logic.update_timestamps (recursive if checked)
          └─ fs_logic.set_attributes
              └─ on_save_finished → refresh_item → update_details_ui

User renames inline in tree
  └─ setData (EditRole)
      └─ fs_logic.rename_file → os.rename
          └─ dataChanged emitted → view updates
```

### State management

All application state lives in `MainWindow` instance variables:
- `self.selected_info: FileInfo` — the currently selected item's data.
- `self.selected_index: QModelIndex` — the tree index of the selected item.
- `self.model: FileTreeModel` — the active tree model (rebuilt on each "Open Folder").
- `self.prop_worker / self.save_worker` — references to active `QThread` workers to prevent garbage collection during async operations.

### Threading model

| Worker          | Purpose                                  | Signals                         |
|-----------------|------------------------------------------|---------------------------------|
| `PropLoadWorker` | Loads 320 Windows Shell properties via COM | `finished(FileInfo)`            |
| `SaveWorker`    | Writes timestamps + attributes to the filesystem | `finished(bool, str)`    |

Both workers are `QThread` subclasses instantiated per-operation and cleaned up automatically after `finished` fires.

### Error handling

- `FileInfo.__init__` catches all exceptions from `os.stat` and `win32api.GetFileAttributes`, defaulting to zero values rather than crashing.
- `load_extended_properties` catches COM errors silently (prints to stderr), leaving `all_properties_loaded = False`.
- `update_timestamps` and `set_attributes` re-raise after printing; `SaveWorker.run` catches any exception and emits `finished(False, str(error))`.
- `set_attributes` specifically checks for `"Access is denied"` and appends a suggestion to run as Administrator.
- `get_directory_contents` catches `PermissionError` and generic exceptions, returning an empty list so unreadable directories do not crash the tree.

## How It Works

1. **Launch** — `main.py` creates a `QApplication`, instantiates `MainWindow`, and enters the Qt event loop. The window displays a dark placeholder screen with a single "Open Folder" button in the toolbar.

2. **Open a folder** — Clicking "Open Folder" triggers `QFileDialog.getExistingDirectory`. The selected path is passed to `FileTreeModel`, which scans the top-level children (lazy — deeper levels are loaded on demand). The UI switches from the placeholder to the content page: a `QSplitter` with the tree on the left and an empty detail panel on the right.

3. **Browse the tree** — The `QTreeView` displays five columns: Name, Size (auto-scaled B/KB/MB/GB/TB), Type (derived from extension or "Folder"), Modified timestamp, and attribute letters (R/H/S/A/C/E). Expanding a node triggers `_load_children` for that directory only. Directories sort before files, then alphabetically.

4. **Select a file or folder** — Clicking any row triggers `on_selection_changed`. The General tab populates synchronously with the item's name, full path, three timestamps (Creation/Modified/Accessed), and four attribute checkboxes (Read-only, Hidden, System, Archive). Simultaneously, a `PropLoadWorker` thread begins loading up to 320 Windows Shell extended properties (EXIF, document metadata, media info, etc.) via the `Shell.Application` COM interface. An indeterminate progress bar animates during loading.

5. **Edit metadata** — Users can:
   - Change any of the three timestamps using the calendar popup of `QDateTimeEdit`.
   - Toggle the four file-attribute checkboxes.
   - Check "Apply recursively" (only enabled for directories) to propagate timestamp changes through the entire subtree.
   - Rename files directly in the tree (inline editing on the Name column).

6. **Apply changes** — Clicking "Apply Changes" constructs a `SaveWorker` thread that calls `fs_logic.update_timestamps` (using `os.utime` for access/modify and `win32file.SetFileTime` for creation) and `fs_logic.set_attributes` (using `win32api.SetFileAttributes`). On success, the tree model refreshes the item and the detail panel updates to reflect the new values.

7. **Extended properties** — Once loaded, the All Properties tab displays every property returned by the Windows Shell (property name → value pairs, sorted alphabetically). A search bar at the top filters rows in real-time by matching against both key and value text.
